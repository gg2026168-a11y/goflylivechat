# 工作人员工号核验合并计划

## Context

用户上传的代码是“客服工号 + 姓名”的工作人员身份核验演示页，包含工号格式校验、输入状态、结果资料卡和工作台按钮，但使用 `STAFF_DB` 与 `setTimeout` 模拟，没有真实接口。当前后台已经具备登录鉴权、人员档案管理、证件查验、最近记录及脱敏导出。用户已选择**整合到现有后台**：保留现有证件查验，新增工作人员工号模式及真实后端资料，不新增公开页面，不引入演示人员或模拟结果。

## 实施方案

### 1. 工作人员资料模型

修改 [models/person_verification.go](file:///workspace/models/person_verification.go) 和 [import.sql](file:///workspace/import.sql)：

- 幂等新增 `person_staff_profile` 一对一资料表：`registry_id` 主键、团队、角色、入职日期、权限 JSON、创建及更新时间；不修改现有 `person_registry` 和 `person_verification` 表，存量数据库只需执行新表语句。
- 为人员档案增加可选的工作人员资料关联；查验记录表结构保持不变，仍只持久化脱敏工号、查验结果和操作人。
- 不保存固定“在职时长”或头像：时长根据入职日期动态计算，头像使用姓名首字符。
- 档案新增/编辑与工作人员资料写入放在同一 GORM 事务中，任一步失败整体回滚；改成非工号类型时同事务删除资料，状态切换保留原资料。
- 档案列表返回工作人员资料，供后台编辑回填；不插入上传代码中的 `STAFF_DB` 示例人员。

### 2. 后端工号查验

修改 [controller/person_verification.go](file:///workspace/controller/person_verification.go)，复用现有路由，不新增公开接口：

- 证件类型新增 `staff_id`，统一去除空白并转大写，校验 `^DY[0-9]{4,6}$`；工号继续使用现有 HMAC-SHA256 规则，不明文落库或返回，脱敏时仅保留 `DY` 前缀和末两位。
- 工作人员姓名沿用上传统一规则：中文 2-10 字，或英文 2-20 个字母（允许空格和点）。查验事由新增“工作人员身份核验”。
- 档案表单在 `staff_id` 模式下校验必填团队、角色、非空且去重的权限，以及合法且非未来的入职日期；权限以 JSON 数组保存，响应时返回数组和动态在职时长。
- 沿用 `POST /person_verify` 与 `matched/not_found/review_required`。工号不存在返回 `not_found`；姓名不符、档案停用或资料缺失返回 `review_required`。
- 仅 `staff_id + matched` 时，在现有查验响应中追加 `staff_profile`（团队、角色、入职日期、在职时长、权限），不返回完整工号或哈希。
- CSV 类型映射补充“工作人员工号”，其余记录及导出结构不变。

### 3. 后台页面合并

修改 [admin.html](file:///workspace/admin.html)，复用现有 `personFetch`、`personData`、档案管理和结果状态：

- 查验与档案类型下拉增加“工作人员工号”。选择后动态显示“客服工号”、示例占位和格式提示，查验事由自动设为“工作人员身份核验”；切回证件类型后恢复原字段。
- 档案表单在工号模式显示团队、角色、入职日期和权限输入；编辑时回填真实资料，状态启停不丢失资料。
- 移植上传代码的输入成功/错误状态、核验中状态及资料卡视觉结构，但继续使用真实 `fetch`，不引入模拟延时。
- 工号查验成功时显示头像、姓名、角色、脱敏工号、在职时长、团队、权限及查验时间；其他结果继续显示现有三态提示，不展示工作人员资料。
- 仅工号查验成功时显示“进入客服工作台”按钮，跳转 `agent.html`；不采用上传代码的 `NEXT_URL='index.html'`。
- 所有动态内容继续使用 `textContent` 或 `escapeHtml`，不回填完整工号。

## 验证

1. 执行 `gofmt`、`go build ./...`，检查后台 JavaScript 语法、元素 ID 唯一性和接口绑定。
2. 在 MySQL 可用环境重复执行新表语句，确认旧人员档案及查验记录不受影响。
3. 验证工号格式错误、未知工号、姓名不符、档案停用、资料缺失和正常匹配六类场景。
4. 验证工作人员档案新增、编辑、启停及事务回滚；确认权限去重、在职时长和资料卡正确，旧四类证件查验及 CSV 导出回归通过。
5. 确认完整工号不出现在数据库、接口响应、档案列表、查验记录或 CSV 中，工作台按钮仅在真实核验成功后可用。
