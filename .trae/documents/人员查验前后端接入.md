# 人员查验前后端接入计划

## Context

[admin.html](file:///workspace/admin.html) 的“人员查验”目前仅展示演示结果、静态记录和待补充的导出按钮。用户已确认采用**内部档案比对**，并通过**后台页面维护人员档案**。本次将接通 Go/GORM 后端与后台页面，实现档案新增、编辑、启停，人员查验、最近记录及脱敏导出；查验结论只代表与内部档案的匹配结果，不宣称公安认证或身份真实性认证。

## 实施方案

### 1. 数据表与模型

- 新增 `models/person_verification.go`，复用现有 `models.Model`、全局 `DB` 和 `SingularTable` 约定，定义：
  - `person_registry`：姓名、证件类型、证件 HMAC、脱敏证件号、状态（`active`/`disabled`）、时间戳；对证件类型与 HMAC 建唯一索引。
  - `person_verification`：姓名、证件类型、脱敏证件号、查验事由、关联档案 ID、结果、操作人 ID/姓名、时间戳；按创建时间建立索引。
- 在 [import.sql](file:///workspace/import.sql) 追加幂等建表语句，不增加自动迁移。存量数据库只执行新增表的语句，不重跑完整安装 SQL。
- 证件号不明文落库、不出现在响应或日志中。使用服务端环境变量 `PERSON_REGISTRY_HMAC_KEY` 计算 HMAC-SHA256；密钥缺失时相关接口返回明确配置错误，密钥需保持稳定。

### 2. 后端接口

新增 `controller/person_verification.go`，并在 [router/api.go](file:///workspace/router/api.go) 注册以下接口，全部复用 `middleware.JwtApiMiddleware`，操作人从 token 中获取：

- `GET /person_registries`：返回脱敏档案列表。
- `POST /person_registries`：新增人员档案。
- `PUT /person_registries/:id`：修改姓名、证件、状态；证件字段留空时保留原证件。
- `POST /person_verify`：按姓名、证件类型、证件号执行内部档案比对并保存查验记录。
- `GET /person_verify_records`：倒序返回最近查验记录。
- `GET /person_verify_export`：导出仅含脱敏证件号的 CSV。

统一校验姓名长度、证件类型和查验事由白名单；身份证校验格式及校验位，护照/其他证件校验长度和字符，手机号码复用现有手机号规范化与正则。所有模型方法返回数据库错误，写库失败不得返回查验成功。

查验结果固定为：
- `matched`：有效证件匹配且姓名一致，显示“内部档案一致”。
- `not_found`：未找到证件档案，显示“未找到内部档案”。
- `review_required`：姓名不一致或档案已停用，显示“待人工复核”。

所有通过输入校验的查验尝试均保存记录；接口沿用 `{code, msg, result}` 响应结构，并正确处理 HTTP 状态和业务状态码。

### 3. 后台页面

修改 [admin.html](file:///workspace/admin.html)，复用现有 `toast()`、`escapeHtml()`、对话框、表格和状态样式：

- 将“导出记录”改为真实按钮，新增“档案管理”入口及对话框。
- 档案管理支持新增、编辑、启用/停用；列表只显示脱敏证件号，编辑时不回填完整证件，只有输入新证件时才更换。
- 查验表单增加明确的证件类型值及手机号选项；提交时显示加载状态并防止重复提交，结果区动态展示三类结论、查验时间和操作人。
- 移除静态查验记录，进入“人员查验”页时加载真实最近记录，提供加载、空数据、失败重试状态；成功查验后刷新记录。
- 请求统一携带 `localStorage.token`，同时检查 HTTP 状态和 `payload.code`；未登录或 token 失效时提示并跳转 `/login`。
- 导出通过携带 token 的 `fetch` 获取 CSV Blob，不在 URL 中传 token；动态内容使用 `textContent` 或现有 HTML 转义函数。

本次不修改 [index.html](file:///workspace/index.html) 的公开前台入口，避免开放未授权的档案查询或查验记录。

## 验证

1. 对新增 Go 文件执行 `gofmt`，运行 `go test ./...` 或至少完成全项目编译检查。
2. 在具备 MySQL 的环境执行新增建表语句、配置 `PERSON_REGISTRY_HMAC_KEY` 后启动服务。
3. 浏览器验证档案新增、编辑、停用/启用，以及 `matched`、`not_found`、`review_required` 三种查验结果。
4. 验证重复提交、非法证件、空记录、数据库失败、无 token/过期 token 的错误状态。
5. 检查最近记录倒序刷新和 CSV 导出，确认页面、接口、CSV 与数据库记录均不泄露完整证件号。
